# flow 习惯打卡 · 需求分析（MVP）

> 版本：v0.1（2026-10-25）  
> 状态：已确认并实现（2026-10-25）  
> 目标：在现有 flow 里加一个**足够简单**的习惯打卡模块，覆盖每天/每周固定日打卡、补卡、取消、周视图、月视图。

---

## 1. 背景与目标

flow 目前只有待办。待办解决“事情”，习惯解决“重复发生的行为”，两者数据结构和使用节奏不同，应该做成独立模块，而不是混进 Tasks 列表。

第一版目标：

1. 能创建习惯，选择“每天”或“每周固定几天”。
2. 今天能一键打卡、取消。
3. 忘记打卡时能补卡；点错时能取消并撤销。
4. 能按周、按月回看完成情况。
5. 和现有 Tasks / Settings 共用一套导航、主题、语言和本地存储。

第一版不做：

- 提醒 / 推送通知
- 云端同步 / 账号
- 习惯量化（喝 8 杯水、跑 5 公里）
- 每次打卡写备注
- 一天多次打卡
- 社交、排行榜、成就体系
- 自定义图标 / 颜色 / 拖拽排序
- 复杂的周期历史（修改周期后回溯旧规则）

---

## 2. 用户场景

| 场景 | 用户动作 | 期望 |
|---|---|---|
| 每天阅读 | 创建“每天”习惯，今天点一下 | 列表里立刻变成已打卡，刷新后还在 |
| 每周一三五健身 | 创建“每周”习惯，勾选一、三、五 | 只有这三天算计划日，其余显示休息 |
| 昨天忘了打卡 | 打开周视图，点昨天 | 补卡成功，可撤销 |
| 点错了 | 再点一次已打卡的日期 | 取消打卡，可撤销 |
| 月底回看 | 切到月视图 | 看到哪些天打卡、哪些计划日没打 |
| 换手机语言 | 在 Settings 切中文 | 习惯模块全部中文，打卡数据不变 |

## 4. 核心概念与规则

### 4.1 概念

- **习惯（Habit）**：一个要重复做的行为，例如“阅读 20 分钟”。
- **计划日（Planned day）**：按频率算出来“应该做”的日期。
- **休息日（Rest day）**：频率之外的日期，不要求打卡，也不计入完成率。
- **打卡记录（Check-in）**：某个习惯在某一天已完成，一天最多一条。
- **补卡**：给过去某个计划日新增打卡记录。
- **取消打卡**：删除某天的打卡记录。
- 习惯与待办数据完全独立，不进入 Tasks 列表，也不参与待办的进行中/已完成统计。

### 4.2 频率

只支持两种：

| 类型 | 规则 |
|---|---|
| 每天 | 从创建日起，每天都是计划日 |
| 每周 | 用户勾选周一至周日中的若干天，至少 1 天；勾选的天是计划日 |

- 一周从**周一**开始。
- “每周 7 天”等价于“每天”，创建时归一为 `daily`。
- 不支持“每周 3 次、不固定哪天”“每隔 N 天”这种弹性频率。

### 4.3 打卡规则

| 规则 | 约定 |
|---|---|
| 开始日期 | 习惯创建当天，不允许回填创建前的日期 |
| 可打卡日期 | 计划日、且不晚于今天、且不早于开始日期 |
| 非计划日 | 不能打卡，显示“休息日” |
| 未来日期 | 不能打卡，按钮禁用 |
| 一天多次 | 不允许，同一天只有一条记录 |
| 补卡窗口 | 最近 **30 天**（含今天），且不早于开始日期 |
| 取消打卡 | 任何已打卡且不晚于今天的日期都可以取消；不受 30 天限制 |
| 修改周期 | MVP 简化：历史打卡保留，但计划日按新周期重新计算 |
| 删除习惯 | 二次确认，同时删除该习惯的全部打卡记录 |

### 4.4 连续次数（Streak）

- 单位是“次”，不是“天”，因为每周习惯有休息日。
- 从今天往前数连续已打卡的**计划日**；休息日跳过，不算中断。
- 今天如果是计划日但还没打卡，**不立刻中断**，从昨天继续算（给当天留时间）。
- 遇到第一个“计划日但没打卡”就停止。
- 不早于习惯开始日期。
- 最佳连续记录第一版不做。

示例：每周一三五，过去三周都打卡，这周一也打了，今天是周三还没打 → 连续次数仍然保留，今天打卡后 +1；如果周三过完还没打，周四再看就中断。

### 4.5 完成数

- 周视图：`已打卡计划日 / 本周计划日总数`，包含本周未来还没到的计划日。
- 月视图：`已打卡计划日 / 本月计划日总数`，包含本月未来还没到的计划日。
- 只统计计划日，休息日不进入分母。
- 不展示百分比，避免月初看起来“完成率很低”；只展示 `3 / 5` 这样的计数。

- 习惯详情页保留底部导航，方便直接切回任务或设置。

## 6. 页面需求

### 6.1 习惯列表

**目标**：一眼看到今天要做什么，快速打卡。

结构：

- 标题 `Habits` / `习惯`
- 副标题：今天 `3 / 5`（今天计划日中的完成数）；今天没有计划日时显示 `Rest day` / `休息日`
- 习惯列表，按创建时间排序（第一版不做拖拽排序）
- 新建按钮：复用现有 FAB 样式，位于底部导航上方

单行结构：

```
[今天打卡圆钮]  习惯名称
                每周一、三、五 · 连续 6 次
```

- 左侧圆钮：
  - 计划日未打卡：空心圆，可点
  - 已打卡：绿色实心 + 勾
  - 休息日：灰色短横线，不可点
- 点击圆钮：今天打卡 / 取消（带撤销 Toast）
- 点击整行：进入详情
- 习惯名称不做删除线，打卡完成不代表“事情结束”
- 名称过长单行截断，详情里完整显示
- 空状态：图标 + “还没有习惯” + “创建第一个习惯”

### 6.2 新建 / 编辑习惯

用底部弹层，延续现有 `AddTodoSheet` 的交互和尺寸。

字段：

1. **名称**
   - 必填，1–40 字
   - placeholder：`比如：阅读 20 分钟` / `e.g. Read for 20 minutes`
2. **频率**
   - 分段控件：`每天 / Every day`、`每周 / Specific days`
3. **星期选择**（仅“每周”）
   - 周一至周日 7 个胶囊，多选
   - 至少选 1 天，否则保存按钮禁用
   - 选中用 accent 浅底
4. **保存**
   - 新建：`创建习惯`
   - 编辑：`保存修改`

规则：

- 编辑时可以改名、改频率、改星期。
- 不提供开始日期编辑。
- 编辑频率时给出轻提示：`修改周期会重新计算历史计划日`（MVP 简化说明）。
- 不做颜色、图标、备注字段。

### 6.3 习惯详情

顶部：

- 返回按钮
- 习惯名称
- 频率描述：`每天` / `每周一、三、五`
- 编辑按钮
- 底部：删除习惯（文字按钮，二次确认）

统计行（三个数字）：

- `连续 6 次` / `Streak 6`
- `本周 3 / 5`
- `累计 42 次`

视图切换：

- 分段控件：`周 / Week`、`月 / Month`
- 默认周视图

#### 周视图

- 一行 7 天，周一 → 周日
- 每格：星期、日期、状态圆点
- 顶部：`10月20日 – 10月26日`，左右切换上一周/下一周，`今天` 快捷按钮
- 状态：
  - 已打卡：绿色实心 + 勾
  - 计划日未打卡：空心圆
  - 休息日：小圆点/短横，置灰
  - 未来：更浅的样式，不可点
  - 开始日期之前：空白/禁用
- 点击可打卡的日期：
  - 今天：打卡 / 取消
  - 过去 30 天内：补卡 / 取消
  - 超过 30 天：不可补卡，Toast 提示 `只能补最近 30 天`
  - 未来：不可点
- 底部或顶部显示 `本周 3 / 5`

#### 月视图

- 7 列日历，周一开头
- 顶部：`2026年10月`，左右切换月份，`今天` 快捷按钮
- 状态与周视图一致，但更紧凑
- 点击日期规则与周视图一致
- 显示 `本月 12 / 20`
- 当月开始日期之前的格子禁用
- 未来计划日可以用很淡的描边显示，提醒“还没到”

#### 图例（可选但建议）

底部一行小图例：

- `✓ 已打卡`
- `○ 计划`
- `· 休息`

手机上如果空间紧张可以隐藏图例，用标题说明。

### 6.4 补卡 / 取消的交互

统一规则：

- 点击可操作日期 → 立即写入并弹 Toast。
- Toast 文案：
  - 今天打卡：`已打卡`
  - 补卡：`已补卡 · 10月20日`
  - 取消：`已取消打卡`
- Toast 带 `撤销`，5 秒内可恢复。
- 超出补卡窗口：不写入，只提示。
- 未来 / 休息日：不响应点击，按钮禁用，`aria-disabled`。
- 取消已打卡的过去日期，不限制 30 天窗口。

### 6.5 删除习惯

- 从详情页底部的 `删除习惯` 进入。
- 确认框标题：`删除这个习惯？`
- 说明：`习惯和它的全部打卡记录会被删除，且无法恢复。`
- 确认按钮用危险色。
- 删除后回到习惯列表。

### 6.6 空状态 / 异常

| 状态 | 表现 |
|---|---|
| 没有习惯 | 图标 + 文案 + 创建按钮 |
| 今天没有计划日 | 列表正常展示，顶部显示 `休息日` |
| 月份早于开始日期 | 日历可看，但全部禁用；提示 `这个习惯从 10月25日 开始` |
| 习惯不存在 | 回到列表，Toast 提示 |
| 本地数据损坏 | 忽略无效记录，至少保证页面可用 |

## 7. 数据模型

### 7.1 类型

```ts
// 周一 = 1 ... 周日 = 7
type Weekday = 1 | 2 | 3 | 4 | 5 | 6 | 7

type HabitSchedule =
  | { type: 'daily' }
  | { type: 'weekly'; weekdays: Weekday[] }

interface Habit {
  id: string
  name: string
  schedule: HabitSchedule
  startDate: string        // YYYY-MM-DD，本地日期
  createdAt: number
  updatedAt: number
}

// habitId -> 打卡日期列表，日期去重、升序
type HabitCheckins = Record<string, string[]>
```

### 7.2 存储

| Key | 内容 |
|---|---|
| `flow.habits.v1` | `Habit[]` |
| `flow.habitCheckins.v1` | `HabitCheckins` |

- 与 `flow.todos.v1`、`flow.locale.v1` 独立。
- 不存“完成状态”的布尔值，只存日期字符串。
- 统计值全部实时计算，不落库，避免不一致。
- 日期一律用本地日历日 `YYYY-MM-DD`，不存 UTC 时间戳；避免跨时区后打卡日漂移。

示例：

```json
{
  "habitId": "habit-1",
  "name": "Read 20 minutes",
  "schedule": { "type": "weekly", "weekdays": [1, 3, 5] },
  "startDate": "2026-10-20",
  "createdAt": 1792860000000,
  "updatedAt": 1792860000000
}
```

```json
{
  "habit-1": ["2026-10-20", "2026-10-22", "2026-10-24"]
}
```

### 7.3 校验

- `name.trim()` 后 1–40 字符。
- `startDate` 必须是合法本地日期。
- `weekly.weekdays` 去重、范围 1–7、至少一个。
- 打卡日期必须是合法 `YYYY-MM-DD`，去重，且不晚于今天。
- 读取时清理不存在的 habitId 记录。
- 删除习惯时同步删除对应 checkins。

## 8. 核心逻辑

### 8.1 是否计划日

```ts
function isScheduled(habit: Habit, dateKey: string): boolean {
  if (habit.schedule.type === 'daily') return true
  return habit.schedule.weekdays.includes(weekdayOf(dateKey)) // 1..7
}
```

### 8.2 某天能否操作

```ts
type DayState =
  | 'checked'       // 已打卡
  | 'available'     // 计划日，可打卡/补卡
  | 'rest'          // 休息日
  | 'future'        // 未来
  | 'before-start'  // 早于开始日期
  | 'out-of-window' // 过去超过 30 天
```

判断顺序：

1. 早于 `startDate` → `before-start`
2. 晚于今天 → `future`
3. 已打卡 → `checked`（即使修改周期后这天不再是计划日，也允许取消）
4. 不是计划日 → `rest`
5. 今天或最近 30 天内 → `available`
6. 其他 → `out-of-window`

### 8.3 连续次数

```ts
function currentStreak(habit, checkins, today): number {
  let count = 0
  let cursor = today

  // 今天计划日但未打卡：宽限到当天结束，从昨天开始数
  if (isScheduled(habit, today) && !hasCheckin(habit, today)) {
    cursor = addDays(today, -1)
  }

  while (cursor >= habit.startDate) {
    if (!isScheduled(habit, cursor)) {
      cursor = addDays(cursor, -1)
      continue
    }
    if (hasCheckin(habit, cursor)) {
      count += 1
      cursor = addDays(cursor, -1)
    } else {
      break
    }
  }
  return count
}
```

### 8.4 周 / 月完成数

- 生成区间内所有日期。
- 过滤：`>= startDate` 且 `isScheduled`。
- 分母 = 计划日总数（包含未来）。
- 分子 = 其中已打卡的数量。
- 休息日不参与。

## 9. 视觉与交互规范

全部复用现有设计令牌，不新增颜色体系：

- 已打卡：`--accent` 实心 + 勾，文字色 `--on-accent`
- 计划日：`1px` 边框 `--line-strong` / `--checkbox-border`
- 休息日：`--text-3` 的小圆点或短横，透明度更低
- 未来：`opacity-40`，禁用
- 今天：外圈 `--line-strong` 或 accent 细环
- 删除：沿用 `--danger`
- 卡片：沿用 14px 圆角、1px 边框、surface 背景
- 周/月日历用等宽数字（`tabular-nums`），避免切换日期时抖动

交互：

- 移动端点击目标尽量 ≥ 44px；日历格子至少 36×36，并带可点击内边距
- 所有日期按钮带 `aria-label`（完整日期 + 状态）
- 已打卡使用 `aria-pressed="true"`
- 禁用状态使用 `aria-disabled`，不要只靠颜色
- Toast 带 `撤销`
- 保留现有 `prefers-reduced-motion` 处理

文案：

- 英文默认，中文可切
- 习惯名称是用户输入，不翻译
- 日期、星期、月份用 `Intl` 按当前语言格式化
- 新增 i18n key 组：`nav.habits`、`habits.*`

## 10. 边界情况

- 习惯在周日创建，周视图本周只有一天是计划日。
- 每周习惯只选一天，周期跨月。
- 月份切换遇到 28/29/30/31 天。
- 补卡跨月、跨年。
- 修改周期后，历史计划日重算（MVP 已知限制）。
- 删除习惯时，删掉该习惯的全部记录。
- 同一天重复打卡：幂等，不新增第二条。
- 快速连点打卡/取消：以最终状态为准，不产生重复记录。
- 设备时区变化：按本地日期记录，不按 UTC。
- 未来日期不可操作。
- 习惯开始前的日期不可操作。
- 习惯名称含 emoji 或长英文：列表截断，详情换行。
- 大量习惯（50+）：列表滚动，不做虚拟化。

## 11. 验收标准

- [ ] 创建“每天”习惯，今天出现在列表，点击打卡，刷新后仍是已打卡。
- [ ] 创建“每周一、三、五”习惯，只有这三天是计划日，其他天显示休息。
- [ ] 每周习惯未选任何星期时不能保存。
- [ ] 今天打卡后可以取消，Toast 可撤销。
- [ ] 周视图能看本周 7 天，左右切换周，今天高亮。
- [ ] 月视图能看整月，左右切换月，今天高亮。
- [ ] 最近 30 天内的计划日可以补卡；超过 30 天不可补卡，并有提示。
- [ ] 未来日期、休息日、开始日期之前均不可点击。
- [ ] 取消过去的打卡后，连续次数和完成数立即更新。
- [ ] 连续次数按计划日计算，休息日不中断；今天未打卡不立即中断。

## 13. 需要你确认的点

下面是我建议的默认值，确认后按这个做：

1. **补卡窗口**：最近 30 天（含今天）。  
   如果想要更严格可以改 7 天，或改成“仅本月”。
2. **休息日是否允许额外打卡**：不允许。休息日就是休息，不计入完成数。  
   如果你希望“今天想多练一次也能记”，需要额外定义“额外打卡”。
3. **修改周期是否影响历史**：MVP 建议全局重算计划日，历史打卡保留。  
   如果要“只影响修改之后”，需要存周期历史，复杂度会明显增加。
4. **一周从周几开始**：周一。和现有日期选择器一致。
5. **删除还是归档**：MVP 直接删除 + 二次确认。  
   如果想要保留历史，可以后加“归档”。
6. **连续次数宽限**：今天还没打卡不立即中断，过了今天才算断。
7. **颜色/图标**：MVP 不做，所有习惯统一视觉；后续再加。
8. **提醒**：第一版不做。

如果以上都同意，我就按 M1 → M4 开始实现。
